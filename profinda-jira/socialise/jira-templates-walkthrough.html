Jira as the single source of truth

A shared, de-duplicated template system for Epics, Stories, Tasks & Sub-tasks — usable the same way by people and AI agents.

Why we're doing this

Our tickets should carry the thinking — not just the task

Today the way we document work in Jira is inconsistent, duplicated, and disconnected from how we increasingly build: with AI. This is a proposal to fix the templates, trim the Jira config, and make one workflow that humans and agents share.

📐 Consistent

One template per level, no repetition. Everyone — and every agent — fills the same thing the same way.

🧠 Durable

The plan and the reasoning live in Jira, not on someone's laptop. Survives handoffs, holidays, and dead hard drives.

🤖 AI-ready

Agents read and write the same tickets. Jira becomes the shared memory for autonomous work.

What's not working today

Three kinds of waste in our current setup

1 Redundancy between levels

The Epic, Story and Task templates each repeat the same sections — Requirements, Technical Design, Risk, Approval — almost word for word.

Maintaining the same content in three places guarantees it drifts out of sync. Which copy is true?

2 Description vs Jira fields

Things Jira already has a field for — t-shirt size, estimate, Product Manager, release notes, fix version, dependencies — get re-typed into the description too.

Two homes for one fact. They disagree the moment one is edited.

3 A noisy Jira config

The create screen for a Story or Task shows ~35 fields — many are reporting fields (QA Points, Blocked Cause, Product Review, Department…) that don't belong at creation.

Required fields are inconsistent across issue types. Creating a ticket is slow and error-prone.

4 Story = Task, byte for byte

The Story and Task templates are currently identical. There's nothing that tells you a Story is user-facing and a Task is internal technical work.

The bigger problem

Humans and AI are documenting work in different worlds

Even where a template exists, it isn't shared, let alone enforced. So everyone improvises — and now the agents improvise too, differently.

● Today — disconnected
  • People create Epics manually, each in their own style.
  • AI agents create tickets a different way again.
  • The template isn't shared or enforced — so nothing matches.
  • Plans live in PLAN.md files on a laptop, or in a chat window that closes.
  • When someone goes on holiday, the thinking goes with them.
  • Progress is invisible unless you ask the person.
● Proposed — one shared workflow
  • One template per level, shipped as a skill — people and agents use the same one.
  • The plan lives in the Story/Task, not on a disk.
  • The steps live in sub-tasks (or a checklist) — visible and resumable.
  • Agents keep Jira updated as they work: Jira becomes the source of truth for progress.
  • Anyone — or any agent — can pick up exactly where it was left.
  • Dependencies are Jira links; risk is assessed once; sign-off is auditable.

The insight: if we're going to have AI build more of our software, the reasoning and the decomposition are our most valuable record. A plan deleted after merge is that record thrown away. Put it in Jira and it becomes shared memory — for the team now, and for autonomous agents later.

The new model

Write it once, at the level where it belongs

Progressive elaboration: each level adds detail, none repeats it.

Epic · the living PRD Problem · Goals · Personas · Scope · High-level architecture · Risk (once) · Approval

Starts light, grows through 3-amigos & sizing. Can't enter development until complete. Risk & architecture are done here, once.

Story · user-facing UI, public APIs, MCPs — user value, requirements, UX, acceptance criteria, plan

Inherits the Epic's architecture & risk. Owned by Product.

Task · internal technical Devops, non-breaking refactors — end-state, design, rollout/rollback, release-notes gate

Inherits the Epic's architecture & risk. Owned by Engineering.

Sub-task · optional step Objective · spec / thinking · files · verification. Status = progress.

Where an agent or dev captures the thinking for one step. Optional — a checklist works too.

The rules that kill the waste

RuleWhat it removes
Risk & high-level architecture live only on the EpicThe same sections repeated on every Story/Task
Anything with a Jira field stays in the fieldDescription re-typing (points, PM, release notes, fix version)
Dependencies are Jira issue linksFree-text dependency lists that go stale
Child issues & open questions use the native panel / commentsDuplicated lists frozen in the description
The plan lives in the ticket; steps are sub-tasks or a checklistPlans stranded in local PLAN.md files

The payoff

What we unlock when Jira is the source of truth

👥 For the team

Pick up anyone's work from Jira. No "where's the plan?" No lost context when someone's away. Consistent tickets are easier to review, report on, and estimate.

🤖 For AI-assisted work

Agents read the Epic → Story/Task → sub-task chain and know exactly where things stand and what to do next. They update progress as they go.

📊 For Product & delivery

Effort-per-customer and effort-per-pod actually work, because attribution sits on the estimate-bearing issue. Risk is assessed once, deliberately.

🔒 For compliance

Explicit sign-off records satisfy SOC-2 / ISO 27001 change controls — a status change alone never did.

The north star: a future where agents can build from these tickets end-to-end — because the problem, the plan, the steps and the reasoning are all captured, consistently, in one place. We build that corpus by working this way now.
